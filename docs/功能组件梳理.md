# RunEver 功能组件梳理

> **口径来源**：2026-10-04 用户口径（思维导图「RunEver-动态右键」功能清单 + 用户重述的核心逻辑）。
> **用法**：§1–§3 是**设计口径**（组件模型 + 判定规格）；§4 是**现状对照**，只用来定位差距，不作为设计依据。
> **现状基线**：AHK 版 `src\*.ahk`（只读参考）+ C# 版 `cs\**`（现役实现），root = `TempSave\runever\`。

---

## 1. 架构总览

```
配置层（只存程序名 / 部分路径）
   └─> 解析层（Everything 索引 → 缓存文件 → 点击期兜底）
          └─> 采集层（热键 → 选中文本 / 文件 / 文件夹 + 前台进程 + 剪贴板）
                 ├─> 直达层（选中文本先正则直达：命中即执行，不弹菜单）
                 └─> 判定层（动态 + 进程 + 固定 三源合成）
                        └─> 执行层（启动软件 / 打开搜索 / 输入文本 / 本地短语搜索 / 快捷键发送）
```

**两条贯穿性设计约束**：
1. **存储只记「程序名 / 部分路径」** —— 不记完整安装路径，换机与多设备同步无需重配。
2. **Everything 不要求常驻后台** —— 索引可由 Everything 本体维护，RunEver 只在需要时查询。

## 2. 组件清单

### C1 · 配置与存储
| 存储 | 内容 | 约束 |
|---|---|---|
| `config\menus.conf` | 分组 + 条目（标题 / 快捷键 / 动作 / 目标） | 目标里的**程序只写程序名**；路径类可写环境变量（`%USERPROFILE%`）或部分路径 |
| `config\auto.conf` | 触发键、自动执行（插件）开关、缺件隐藏、WebDAV 等 | —— |
| `config\functions\*.ahk` | 文本直达插件（正则 → 产出） | —— |
| `cache\paths.txt` | 程序名=全路径 缓存 | 可删可重建，属派生数据 |
| `state\*` | 日志 / 插件登记 / 托盘句柄 | —— |

### C2 · Everything 解析模块
- **后端链**：Everything SDK（`Everything64.dll`）→ `es.exe` → `PATH + App Paths`，逐级降级并记录降级原因。
- **同名多命中**：取**最新创建**的同名文件（原版口径）。
- **缓存策略（用户口径）**：**每次开机运行时 EV 全盘扫一遍 → 落缓存文件**。
- **点击期解析（用户口径）**：**优先查缓存；缓存无或无效 → 当场调 EV 搜索拿路径 → 启动**。

### C3 · 采集模块
输入形态判定（互斥四态 + 进程）：① 纯文本 ② 文件 ③ 文件夹 ④ 文件+文件夹混合 ⑤ 无选中；另取**前台进程名**与剪贴板。

### C4 · 菜单模型（6 类分组）
| 类 | 类型 | 归属 | 语义 |
|---|---|---|---|
| 预设 | `text` | 系统内置 | 文本菜单：选中文本时显示 |
| 预设 | `folder` | 系统内置 | 文件夹菜单：选中文件夹时显示 |
| 预设 | `fallback` | 系统内置 | 公共兜底菜单：动态命中不到时显示 |
| 预设 | `always` | 系统内置 | 固定显示菜单：任何情况都显示 |
| 自定 | `ext` | 用户创建 | 扩展名菜单：按选中文件的扩展名命中 |
| 自定 | `proc` | 用户创建 | 进程菜单：按前台进程命中 |

### C5 · 判定合成模块
最终菜单 = **动态菜单 + 进程菜单 + 固定菜单**，显示顺序 = **动态 → 进程 → 固定**（功能区若有则其后）。

### C6 · 执行模块（动作能力矩阵）
| 能力 | 目标写法 | 参数行为 |
|---|---|---|
| 启动软件 `run` | **只记程序名**（EV 解析最新同名文件） | 支持命令行；**选中文件（夹）/文本自动追加到参数末尾**；可选追加当前进程名 |
| 打开搜索 `url` | 网址模板（含 `http(s)`） | 选中文本注入模板；支持**指定站点的默认搜索引擎**与 `#{搜索引擎名称}` 语法 |
| 输入文本 `send` | 文本 | 直接发送到当前输入框 |
| 快捷键发送 `keys` | 按键序列 | 模拟按键 |
| 启动动作 `action` | 动作（命令 / 脚本 / 插件） | 支持动作参数；选中内容自动追加；可选追加进程名 |

### C7 · 文本直达模块
选中文本**先做直达匹配**：命中 → 直接执行/打开，**不显示菜单**。配置化（正则 + 产出类型 + 优先级）。
原版清单：系统环境变量路径 / `ms-settings`、`shell` 指令 / 快递单号（京东·顺丰·德邦）/ IPv4·IPv6 判断并 ping / URL / 本地路径（含用户名替换）/ 邮箱（打开发信界面）/ 注册表地址（打开 regedit 定位）/ base64 文件头（浏览器打开）/ `=` 开头计算式。

### C8 · 功能区 · 设置 UI · 运维
- **功能区**：本地文件搜索（需设置 Everything 路径；搜选中文件（夹）名 / 选中文本）、快速选择分组。
- **设置 UI**：分组与条目编辑（增删改/排序/层级/实时预览）、插件页、常规页；树内**所有路径类字段提供快速选择**。
- **运维**：托盘菜单（显示菜单 / 设置 / 重载配置 / 刷新路径缓存 / 全盘自检 / 刷新插件 / 配置同步 / 打开各类目录 / 日志）、开机自启、WebDAV 配置同步。

## 3. 判定规格（可逐条验收）

| # | 输入形态 | 应显示的菜单 |
|---|---|---|
| R1 | 选中文本 | 文本菜单（`text`） |
| R2 | 选中文件，扩展名**只命中一个** `ext` 分组 | 该扩展名菜单 |
| R3 | 选中文件，扩展名命中**多个** `ext` 分组 | **公共兜底菜单**（`fallback`） |
| R4 | 选中文件夹 | 文件夹菜单（`folder`） |
| R5 | 文件夹与文件**同时**选中 | **公共兜底菜单** |
| R6 | 未选中任何内容 | 公共兜底菜单 |
| R7 | 前台进程命中 `proc` 分组 | 进程菜单（**单进程只进一个进程分组** ← 规则待定案，见 §5-1） |
| R8 | `always` 分组 | 任何情况都显示 |
| R9 | 合成与顺序 | 动态（R1–R6 命中者）→ 进程（R7）→ 固定（R8） |

**互斥性**：R2/R3/R5/R6 同槽位互斥——动态槽位只会出现「命中的扩展名菜单」或「兜底菜单」之一，不会既有扩展名菜单又有兜底菜单。

## 4. 现状对照（差距清单）

| 口径 | 现状 | 判定 |
|---|---|---|
| R2 / R3 扩展名「唯一命中 vs 多命中」 | `Matcher.cs:88-90` 把**所有**命中的 `ext` 分组全加入 `selectGrps`，无「唯一/多命中」判定 | ❌ 缺规则 |
| R5 文件+文件夹混合 → 兜底 | `Matcher.cs:82-90`：`hasFolder` 与 `exts` 各自独立命中 ⇒ folder 组与 ext 组**同时**显示 | ❌ 缺规则 |
| R7 进程菜单 | `Matcher.cs:91-93` 所有命中的 `proc` 分组全显示；「只进一个」未实现且规则未定 | ❌ 待定案 |
| R1 / R4 / R6 / R8 / R9 | `Matcher.cs:76-105` 已按「动态 → 兜底 → 进程 → 固定」合成 | ✅ |
| C2 开机 EV 全盘扫 | C# `RunEverApp.Init()` 无此步；AHK 仅「缓存为空」才扫（`RunEver.ahk:180-185`） | ❌ |
| C2 点击期 EV 兜底 | AHK `RunEverExec.ahk:326-351`、C# `Executor.cs:87-105` 都只走「缓存 → PATH + App Paths → ShellExecute」，**都不调 EV** | ❌ |
| C6 `#{搜索引擎名称}` / 站点默认引擎 | 全仓无实现（仅原版结构 dump 里出现过） | ❌ |
| C6 选中内容自动追加到启动参数末尾 | 现役只有占位符（`%s %text% %file% %clip% %win% %proc%`）需手动写入目标串，无「自动追加」 | ❌ |
| C7 文本直达 | `AutoMatcher` + `config\functions\*.ahk`（现役 8 个插件：choco-run / local-path / sf-express / url-open / deppon / email / jd-logistics / ms-settings） | ✅ 机制在；原版 10 条清单里的 **ping / 注册表 / base64 / 计算式**未见 |
| C8 功能区（本地文件搜索 / 快速选择分组） | 全仓无实现 | ❌ |
| C1 存储只记程序名 | `run` 条目 ✅；`open` 条目仍存全路径、`ext`/`proc` 存关键词 | ✅ 符合（本条只约束 `run`） |

## 5. 待定案

1. **进程菜单多命中取一**：命中多个 `proc` 分组时怎么办 —— ① 只取配置文件里第一个命中组 ② 取全部但只展开第一个 ③ 显式优先级字段 ④ 仍全显示（放弃「只进一个」）。
2. **扩展名多命中 → 兜底**：是「用兜底菜单**替代**扩展名菜单」，还是「扩展名菜单 + 兜底菜单并存」？本文按**替代**（互斥）写。
3. **点击期 EV 兜底的时延预算**：EV 查询实测 **~200ms**（`--ev-probe`：probe=202ms）——点击路径上直接同步查是否可接受？还是先启动已知的、仅失败时再补查？
4. **开机全盘扫的形态**：全量扫（本次 20 个程序约 3.8s，见 `--selftest-pathcache` 3801ms）放在开机后**后台异步**做，还是保留「增量 + 点击期兜底」？
