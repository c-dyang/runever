# RunAny fork 可行性评估（对照实验 · 2026-10-04）

> **目的**：回答"改 RunAny 到底要改多少"，作为 P3（实现基座）定案依据。
> **方法**：**代码级**评估 —— 逐处读 RunAny v5.8.2 的配置解析 / 菜单索引 / 显示分支，把《架构契约》的每条口径映射到具体行号与改动点。
> **样本**：本机 `%TEMP%\runany-src\RunAny.ahk`，**v5.8.2 @2022-10-22**，381 KB / ≈9983 行（AHK **v1**，要求 1.1.31+）。行号按 read 工具编号。
> **⚠️ 未做运行时验证**：本文全部结论来自源码；"行为是否真如源码所示"需要装官方 RunAny + 配一份 ini 跑 R1–R9 用例才能坐实（见 §6）。

---

## 1. 结论摘要

**RunAny 的菜单模型与本项目口径的同构度**比预期高得多 —— 它的 ini 语法几乎就是我们要的六类分组：

```
-分类名|<关联标记>          ← 我们叫"分组"
   标记 = public           → 公共兜底菜单      MenuObjPublic   (:633)
   标记 = text             → 文本菜单          MenuObjText     (:635)
   标记 = file             → 文件菜单          MenuObjFile     (:637)
   标记 = xxx.exe|xxx.class → 进程/窗口类菜单   MenuObjWindow   (:639-644)
   标记 = 其它后缀          → 扩展名菜单        MenuObjExt      (:646)
```

**要改的不是"菜单层"，而是 4 处索引/消解逻辑 + 1 处主干 + 1 个新段**，估 **300–600 行 AHK v1**（明细见 §4）。真正的代价不在改动量，而在：**AHK v1 代码库 + 1 万行单文件 Gosub 结构 + 零测试网**（改动回归全靠手工）。

## 2. RunAny 菜单模型解剖

| 环节 | 位置 | 做法 |
|---|---|---|
| 配置解析 | `Menu_Read()` :607-700+ | 按 `-`/`--` 层级建菜单树；`\|` 后是关联标记（§1 五种） |
| 索引 | :633-647 | 标记 → 全局表：`public`/`text`/`file`/`xxx.exe`/后缀 |
| 显示入口 | `Menu_Show:` :1169 | 先取选中内容 `getZz:=Get_Zz()`（:1176） |
| 无选中分支 | :1178-1238 | 取前台 **进程名 + 窗口类**（`WinGet ProcessName,A` :1182、`WinGetClass,A` :1183）→ `MenuObjWindow[class]` > `MenuObjWindow[proc]` > 默认根菜单 |
| 选中文件分支 | :1240-1311 | `MenuObjExt[扩展名]`；目录 ⇒ `FileExt:="folder"`（:1243）；**若该菜单只有 1 项 ⇒ 直接执行，不弹菜单**（:1248-1251，即"一键直达"） |
| 选中文本分支 | :1397-1500+ | 直达正则（:1313-1396，含"一键公式计算"）先跑；未命中 → `MenuObjText` 菜单 + `MenuObjWindow[proc]` 项**插入合并**（:1407-1424） |
| 公共兜底 | :1189-1200 / :1261-1272 / :1409-1424 | `MenuObjExt["public"]` 的内容**插入到目标菜单首部** |
| 性能模型 | — | **启动时建树**（`Menu_Var_Set`/`Menu_Read`），显示期只**插入/删除临时项** |

| 契约项 | RunAny | 判定 |
|---|---|---|
| 六类分组语义（text/folder/exe/proc/fallback/ext） | ✅ 一一对应（§1 语法表） | **同构** |
| R1 选中文本 → 文本菜单 | ✅ :1400-1405 | 符 |
| R4 选中文件夹 → 文件夹菜单 | ✅ :1242-1243（`FileExt:="folder"`） | 符 |

| R2 扩展名命中**唯一** → 该菜单 | ✅ :1246 单值查表 | 符 |

| R5 文件+文件夹混合 → 兜底 | ❌ 混合时按"文件分支"走（`Candy_isFile`），无混合判定 | **需改** |

| 8 套自检 / 自动化回归 | ❌ 无任何测试 | **需新增** |

## 5. 值得直接借用的（与是否 fork 无关）

1. **配置语法**：`-分类|public / text / file / xxx.exe / 后缀` —— 已被 1000+ stars / 6 年验证，比我们自定义的 `======` 分组块更省事（可直接作为 `menus.conf` 的兼容写法）。
2. **窗口类名维度**：它用 `WinGetClass` + `xxx.class` 标记（:1183、:639-641），比"只看进程名"更准（同一进程的对话框/主窗可分开），也正好对上"对话框 Ctrl+G 定位"（`#32770`）。
3. **性能做法**：启动时建树 + 显示期只插入临时项（:1255-1287）—— 我们 C# 现在是每次重建（实测 167ms/次），可改为"预建各类子菜单 + 显示时组装"。
4. **无路径应用缓存**：独立 ini + `FileExist` 失效检测 + **一次 regex 批量查询**（:14 节）。
5. **一键直达清单**：IP 地址 ping、网盘提取码识别、公式计算等可直接抄成我们的内置模板。
