## 2. 组件边界（角色与职责）

| 组件 | 职责 | 允许依赖 | 绝不负责 |
|---|---|---|---|
| C1 配置 | 读写 `menus.conf` / `auto.conf` / `functions\*` | 文件系统 | 不做解析、不做判定 |
| C2 解析 | 程序名 → 全路径（后端链 + 缓存 + 现查） | C1、Everything SDK / es.exe | 不做显示决策 |
| C3 采集 | 热键 → 选中文本 / 文件 / 文件夹 + 前台进程 + 剪贴板 | 采集器进程 | 不做判定 |
| C4 模型 | 分组 / 条目 / 上下文的**数据结构** | 无 | 不含行为 |
| C5 判定 | 上下文 + 分组集 → **应显示的菜单组列表** | C4 | 不碰文件系统、不查 EV |
| C6 执行 | 条目 + 上下文 → 动作 | C2（取路径） | 不做判定 |
| C7 直达 | 文本 → 命中即执行（不弹菜单） | C6 | 不参与菜单合成 |
| C8 呈现 | 组列表 → Win32 菜单 → 被点条目 | C4 | 不做判定、不查文件 |
| C9 界面 / 运维 | 设置 UI、托盘、自检、同步 | 全部 | 不内嵌判定规则 |

**硬边界**：C5 判定层**零 IO**（不查文件系统、不调 EV、不读缓存）—— 缺件隐藏所需的解析结果由 C2 以数据形式注入。这条保证判定可纯函数化、可全量单测。

**I-5 热键路径禁阻塞 ✅（2026-10-04 定案，基座选型的决定性约束）**：
- 热键回调内**只做组装**：不得出现任何等待 / 轮询 / 同步 IO / `Sleep` 式兜底；
- 采集走**独立进程**（`CaptureRunner.exe`），EV 查询走**后台线程**，重活一律不在主线程；
- 依据（对照实验）：AHK 系实现把"取选中内容"压在主线 —— RunAny `Menu_Show` → `Get_Zz()`（:1176）→ `ClipWait,%ClipWaitTime%`（:2475，文件管理器场景默认 1.2s :3630，兜底 `ClipWait,2` :2773），启动期 EV 解析还有 `Loop,30{Sleep,100}` 轮询（:232），全文遍布 `Sleep 50/500/1000`；这正是 2026-10-03 AHK 版实测「按键延迟 / 失焦不消失 / 弹出较慢」的成因。

**I-6 菜单项同名共存 ✅（2026-10-04 定案，D11 直接后果）**：一条菜单里允许出现**多个同名条目**（如浏览器组与终端组各有一条「打开 PowerShell」），实现必须靠"**命令 ID 与显示文本分离**"（ID 全局唯一分配），**禁止以显示文本作为菜单项标识**。
> 依据：AHK 系实现的菜单**不允许重复项** —— 这正是用户当年弃 RunAny / AHK 方案的两大根因之一。现役 `Native\NativeMenu`（ID 分配器 + 文本分离）已实测通过"同名项共存 ✓"，重写核心三层时**不得破坏它**，并保留回归用例。

## 4. 解析契约（C2）

**三个触发时机**：
1. **开机**：后台全盘扫一次（新增条目名 + 失效条目重解析）→ 落 `cache\paths.txt`
2. **配置保存后**：自动做一次**增量解析**（只解析新增 / 上次失败的名字）✅ —— 没有这一步，「按缓存隐藏」（D4）会把刚加进来的条目直接隐藏，形成死角
   - **编辑器直连缓存** ✅：编辑页用「浏览」选到**完整地址**时，**直接把完整路径写进缓存**（键 = **剥离扩展名的程序名**），配置文件里只写**剥离后的程序名**；这一步**不触发 EV 查询**（用户已指定路径）
3. **执行期（软件移位兜底）**：`run` 目标在缓存命中但**文件不存在** ⇒ 当场查 EV 一次 → 命中则启动**并回写缓存**；仍未命中 ⇒ 报错（不静默失败）
4. **手动刷新后回灌** ✅（2026-10-04 定案，修原 gap①）：托盘「刷新路径缓存」完成后**必须把新缓存回灌运行实例**（现役缺陷：`PathCacheRefresh.Run` 新建实例落盘，而 app 的 `_cache`/`_icons`/`_executor` 仍是启动时那份内存副本，运行期从不重载）；托盘「重载配置」按"重读全部配置 + 重载缓存"实现（原 gap④：保存 `menus.conf` 后不重解析，需重启）

**后端链**：Everything SDK（`Everything64.dll`）→ `es.exe` → `PATH + App Paths`；逐级降级并**记录降级原因**。

**同名多命中** ✅：按**文件创建时间**降序取第一条（通行操作）。**不加目录排除表**（2026-10-04 定案）—— 接受"新建同名副本会抢占"的代价。
> 已知代价（实测，不修）：本机 `7z.exe` 一次命中 7 条，其中 4 条是我们自己造的测试桩（`TempSave\autoextract-v1.2\**\7z.exe`，创建于 2026-09-29 20:14–20:58），真正的 `C:\Program Files\7-Zip\7z.exe` 创建于 2026-02-12 ⇒ 该场景会解析到测试桩，属预期行为。

**三态**：`Ok`（已解析）/ `Missing`（EV 已确认缺失）/ `Unknown`（后端不可用或不适用）—— `Missing` / `Unknown` 的消费者只在自检窗口，不参与菜单显示（D4）。

**I-7 配置级热加载 ✅（2026-10-04 定案，段 1.7 落地，与 I-5 同层约束）**：

- **判据**：`长度 + LastWriteTimeUtc.Ticks`（**不做哈希** —— 哈希必须读全文件，破 I-5）；`menus.conf` 与 `auto.conf` 同口径。
- **热键路径成本**：两个文件各一次 stat；均未变 ⇒ **0 次解析、0 次读盘**。变了 ⇒ `menus.conf` 一次重解析（不扫插件、不重建匹配器/图标/执行器/缓存）、`auto.conf` 一次整份重读。
- **`menus.conf` 换代**：变了 ⇒ `new ConfParser` + `Parse()` 后**整体换实例**（禁止就地 `Groups.Add/Clear`）；**下列三种情况一律保留上一份成功解析的 `Groups`**（不切换、不清空 —— `menus.conf` 无默认值语义，清空 = 菜单消失；"解出 0 组"含**内容退化 / 0 字节 / 全空白**三种文件形态）：
  1. **文件暂缺**（写盘替换窗口 `tmp → delete → move` / 被删）；
  2. **`Parse()` 抛异常**（截断到分组行 / 未知分组类型 / 语法错）；
  3. **`Parse()` 成功但解出 0 组 —— `Groups.Count == 0`**（典型：被截断到只剩注释行；它**不抛异常**，若不拦就会把菜单换成空表）。判据只用两个**已在函数内捕获的廉价量**：`Groups.Count`（已建好的对象图属性）与 `FileInfo.Length`（本次 stat 的 `len`）——**不额外读盘** ⇒ 不破 I-5。该条**同时覆盖 `len == 0`（0 字节文件）与全空白文件**：二者正是"写盘被打断"的典型形态，放行即产生"菜单没了"，故一律保留旧表；**热键路径不替用户执行清空**（真要清空菜单走显式通道，见下条）。
- **"保留旧表"的边界（勿混）**：上述保守取舍**只覆盖热键路径的自动重载**（`MenuConfWatcher.TryReloadIfChanged`）。**用户显式通道不受此限制，一律按文件实际内容呈现（含空表）**：托盘「重载配置」（`TrayApp.ReloadConfig` → `new RunEverApp(_root).Init()`）与设置窗保存后的重读（`RunEverApp.ReloadMenus`，`new ConfParser` + `Parse` 直读）都**不经** `MenuConfWatcher` ⇒ 用户显式说"就用这份文件"时，按文件呈现才是正确语义。
- **已知窗口（`D-2w`，本段显式用例化、不阻断）**：判据是 `长度 + LastWriteTimeUtc.Ticks` 的**等值比较**，故**内容变了但长度相等且 mtime 完全落在同一刻度**时会被判成"未变"（0 解析、0 换代）。**可达路径**：`cmd copy` / `File.Copy` **继承源文件 mtime**（实测：copy 后目标戳 == 源戳，而非写入时刻）+ 等长内容 + 两次写落在同一系统时钟节拍。该窗口**由 `--selftest-hotreload` 的 `CaseSameTickBoundary`（C7b）显式断言当前行为**（`return false` / `fresh=null` / 引用不变 / `ParseCount` 零增量），不再以随机假红形式出现；**根治（内容指纹旁路）= 下一段**。
- **同一次热键流程只取一次快照**：缺件注入（`PathResolvePolicy.InjectEntryResolved`）与判定（`MatchEngine.Decide`）**必须共用同一实例**（唯一收口 = `MenuDecisionPipeline.InjectAndDecide`）。下标是"相对传入列表"的相对量，跨列表即错位且**不抛异常**（表现为随机隐藏错条目 / 派发出不在当前菜单上的条目）。

**`auto.conf` 的 key → 消费点（三类分栏，不许笼统称"全键实时"）**：

| 类 | 键 | 消费点 | 生效时机 |
|---|---|---|---|
| ① 经 `AutoConf` | `hideMissing` | `RunEverApp.ShowMenuFlow` → `AutoMatcher.LiveShowConf()`（判定层之前） | **下一轮热键必生效**（与选中文本无关） |
| ① | `menuOrder` | 同上（同一份快照）→ `MenuDecision.Flat(order)` | 同上（改完下一次弹菜单即生效） |
| ① | `memTrimIdle` | `RunEverApp` 菜单关闭后 `MemTrim.Schedule(idle)`（后台线程：GC + EmptyWorkingSet） | 下一个 idle 窗口生效；`0` = 关 |

**菜单后端只有一种（2026-11-08 定案）**：固定 Win32 `TrackPopupMenu`；`uiBackend` / `captureBackend` 两个模式开关已删除（旧配置里留着也不读）。
WPF 只用于设置窗口（独立进程 `--settings`）⇒ 托盘进程不加载 WPF/MahApps 菜单栈（省掉首次弹菜单约 60MB 首解析，实测托盘 127MB → 36–45MB）。
**子菜单图标**：popup 项无命令 ID ⇒ `AddSubMenu()` 返回位置索引，`SetFolderIconByPosition()` 按位置写 `MIIM_BITMAP`；图标 = **系统文件夹图标**（`SHGetFileInfo` + `SHGFI_USEFILEATTRIBUTES`/`FILE_ATTRIBUTE_DIRECTORY` → `IconToDib`），与第一个子项无关。
**菜单键盘**：Win32 原生里空格不激活项（回车才激活）⇒ `NativeMenu.Show()` 期间挂线程级 `WH_MSGFILTER`（hMod = 模块句柄），把菜单循环中的 `VK_SPACE`（仅 WM_KEYDOWN、仅 MSGF_MENU）改写成 `VK_RETURN`；弹出即挂、返回即摘。判定核心 `NativeMenu.TryConvertSpace()` 由 `--selftest-menu` 四条断言覆盖。

**`menuOrder` = 三段顺序**（`dynamic` / `process` / `always`）：动态与兜底**同格**（I-1 互斥，都落在 `MenuDecision.Dynamic`），故不给兜底单列一段；旧四段写法里的 `fallback` 词仍可读，归一成 `dynamic`。某段当下为空（未选中且无兜底分组等）则该块被跳过，此时排序无可见变化。
| ① | `waitWhenShown` | 执行器镜像字段 `Executor.WaitWhenShown`（热键期同步） | 同上 |
| ① | `enabled` | `AutoMatcher.Match`（`TryAutoExec` 内） | **需有选中文本**；未选中 ⇒ 本轮不消费 |
| ① | `minLen` | 同上 | 同上 |
| ① | `showByDefault` | 同上 | 同上 |
| ① | `cacheSeconds` | `AutoMatcher.Load`（插件重扫节流判据） | 同上（不影响判定层） |
| ② 各自现读文件 | `espath` / `evdll` | `PathCacheBuilder` / `SearchBackends`（`ReadAutoConfKey`） | 每次解析 / 后端解析时现读 |
| ② | `webdavUrl/User/Pass/Dir` | `WebDavConfig.Load` | 下一轮同步 |
| ③ 生命周期键 | `log` / `loglevel` | `RunEverApp.ReadLogSettings`（启动期读一次） | **需重启托盘** |
| ③ | `syncOnStart` | `TrayApp` 启动流程 | **下次启动** |

**`hotkey` 的生效路径 ✅**：`hotkey` 是**注册期键** —— 由 `TrayApp.ApplyHotkey()`（`:499`）现读 `auto.conf` 重注册，**只有两条调用链**：设置窗口关闭（`:428`）/ 托盘「重载配置」（`:450`）。⇒ **外部编辑 `auto.conf` 不会自动重注册**；改触发键需**关闭设置窗口**或走**托盘「重载配置」**。该键**不进** `AutoConf`（否则形成"文件 vs 内存"两条读取路径）。

## 5. 判定契约（C5）

| # | 输入形态 | 应显示 |
|---|---|---|
| R1 | 选中文本 | `text` 组（唯一） |
| R2 | 选中文件，扩展名只命中 **1 个** `ext` 组 | 该 `ext` 组 |
| R3 | 选中文件，扩展名命中 **≥2 个** `ext` 组 | `fallback` 组 |
| R4 | 选中文件夹 | `folder` 组（唯一） |
| R5 | 文件 + 文件夹**同时**选中 | `fallback` 组 |
| R6 | 无选中 | `fallback` 组 |
| R7 | 前台进程命中 `proc` 组 | 该 `proc` 组（因 D3 校验，**至多一个**） |
| R8 | `always` 组 | 恒显示 |
| R9 | 合成与顺序 | **动态（R1–R6）→ 进程（R7）→ 固定（R8，含功能区）**，堆叠不去重 |

**不变量**：
- I-1 动态槽位**互斥**：R2/R3/R5/R6 只会出现其一 —— 要么命中的 `ext` 组，要么 `fallback`，不会并存。
- I-2 **兜底判定只看动态槽位**是否为空，与进程槽位无关。
- I-3 预设四类各至多一个（D2）；`proc` 进程名跨组不重复（D3）。
- I-4 手改配置造成违规时（如两个 `proc` 组含同进程）：运行时取**配置顺序第一个** + 自检报「非法配置」⏳（不静默丢弃、不弹异常）。

## 6. 执行契约（C6）

| 能力 | 行为 |
|---|---|
| `run` | 程序名 → 解析全路径 → 启动；支持命令行参数 |
| `open` | 打开文件 / 文件夹（多目标按引号分隔） |
| `url` | 模板注入选中文本后打开。**不做** `#{搜索引擎名称}` + 引擎表 —— 那是 Quicker 动作的启动项能力，本实现不覆盖（Q6 定案） |
| `action` | 命令 / 脚本 + 参数；`flag` 控制窗口显示 / 隐藏 |
| `send` | 文本发到当前输入框 |
| `keys` | 模拟按键序列 |
| `evsearch` ⏳ | 调起 Everything 带搜索词显示结果 |

**占位符（与判定层同步维护，唯一源）**：`%s`（优先选中文本，无则剪贴板）`%text%` `%file%` `%clip%` `%win%` `%proc%`

**参数为空 ⇒ 自动追加选中内容 ✅（2026-10-04 修订，原 Q7"不做自动追加"作废）**：
- 规则：`run` / `action` / `open` 三类，**参数留空**时自动追加 —— 选中文件（夹）⇒ 追加其**完整路径**（多个以空格分隔、各自带引号）；选中文本 ⇒ 追加该文本；无选中 ⇒ 不追加。
- 优先级：**参数里显式写了占位符 ⇒ 按占位符替换，不自动追加**（避免重复）；仅当参数为空才自动追加。
- 不适用：`url`（已有 `%s`/模板语义）、`send`、`keys`。
- 编辑器形态：条目编辑把 `Target` 拆成「**文件名**」+「**参数**」两个输入框（尊重引号包裹的带空格路径），保存时用空格拼回 ⇒ **配置文件格式零变更**；文件名框提供**浏览选择**（复用 `Views\PathBox.cs`）。

## 8. 验收基准

3. **可作为成品直接用**：装官方 RunAny 吃掉我们**不打算做**的部分（对话框 Ctrl+G 定位、热键映射、热字符串、网盘智能识别），并充当**行为参照**。
